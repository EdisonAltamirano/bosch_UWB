========================================================================
  SR250 UWB  ─  Session Protocol Notes
  STM32H7 (Nucleo-H745ZI)  ←→  NXP SR250  ←→  ROS2 (Ubuntu)
========================================================================

────────────────────────────────────────────────────────────────────────
1.  WHAT THE PC SENDS TO THE STM32
────────────────────────────────────────────────────────────────────────

Transport : UDP  →  192.168.1.10 : 37249

Packet envelope (8 bytes, little-endian):
  [0-1]  magic          : 0x55 0x57
  [2]    version        : 0x01
  [3]    msg_type       : 0x01 = SET_CONFIG_FULL
                          0x02 = SET_PARAMS_PARTIAL
                          0x03 = START_RADAR
                          0x04 = STOP_RADAR
  [4-5]  seq            : uint16  (rolling, starts at 1)
  [6-7]  payload_len    : uint16  (bytes following this header)
  [8+]   payload        : TLV-encoded config (for SET_CONFIG_FULL)

TLV format inside the payload (each tag):
  [0-1]  tag    : uint16 LE   (see table below)
  [2-3]  length : uint16 LE
  [4+]   value  : `length` bytes, LE integers

Active configuration (defaults in sensors.launch.py)
─────────────────────────────────────────────────────
  Tag 0x0001  CHANNEL_NUMBER          9     (UWB ch 9 ≈ 8.0 GHz)
  Tag 0x0002  PREAMBLE_CODE_INDEX    26
  Tag 0x0003  ANTENNAS_CONFIG_RX    [mode=0x02, num=0x03,
                                     RXC_id=1, RXB_id=2, RXA_id=0]
              RXA=0 means RXA is disabled → 2 active receive antennas
  Tag 0x0004  ANTENNAS_CONFIG_TX    [num=0x01, TX_id=1]
  Tag 0x0005  RADAR_MODE             1     (MEDIUM_DISTANCE)
  Tag 0x0006  SINGLE_FRAME_NTF       0
  Tag 0x0007  RADAR_RFRI            [interval_ms=96, slot_dur=14400, slots=4]
  Tag 0x0008  CIR_NUM_SAMPLES      128     (taps per measurement)
  Tag 0x0009  RADAR_RX_GAIN        [agc_mode=0, rxa=0, rxb=0, rxc=0]
  Tag 0x000A  CIR_START_OFFSET     [rxc=0, rxb=0, rxa=0]
  Tag 0x000B  RADAR_PERFORMANCE     0x03
  Tag 0x000C  DRIFT_COMPENSATION   0x0CCD
  Tag 0x000D  PRESENCE_DET_CFG     mode=0x00  (DISABLED  ─  CIR only)

After SET_CONFIG_FULL is acknowledged, the PC sends START_RADAR (no
payload).  The STM32 then calls uci_radar_start() and the SR250 begins
measuring.

────────────────────────────────────────────────────────────────────────
2.  WHAT THE STM32 SENDS BACK TO THE PC
────────────────────────────────────────────────────────────────────────

Transport : UDP  →  <source IP of last command> : 20001 (ACK/ERROR)
                                                 : 20000 (RADAR_FRAME)

2a.  ACK / ERROR  (port 20001)
────────────────────────────────
  Envelope as above; msg_type = 0x05 (ACK) or 0x06 (ERROR)
  ACK payload:   [acked_msg_type:1][seq:2]
  ERROR payload: [failed_msg_type:1][seq:2][error_code:2][detail:1]

  Common error codes:
    0x0001  invalid magic
    0x0005  missing required TLV field
    0x0006  invalid state (e.g. START before config)
    0x0007  UCI command to SR250 failed

2b.  RADAR_FRAME  (port 20000, once session is running)
─────────────────────────────────────────────────────────
  [Envelope  ─  8 bytes]
    magic[2]          0x55 0x57
    version[1]        0x01
    msg_type[1]       0x07  (RADAR_FRAME)
    seq[2]            rolling (always 0 in current firmware)
    payload_len[2]    total bytes below

  [RADAR_FRAME header  ─  8 bytes]
    session_handle[4] handle assigned by SR250 (e.g. 0xF0000001)
    status[1]         0x00 = OK
    radar_data_type[1]  0x00 = CIR  |  0x01 = PRESENCE  |  0x20 = ANT_ISO
    raw_len[2]        length of the UCI notification payload that follows

  [UCI RADAR_RX_NTF payload  ─  raw_len bytes]
    session_handle[4]  (same as above)
    status[1]
    data_type[1]
    num_samples[2]     number of TX-RX antenna pairs in this notification
                       With 2 active RX × 1 TX  →  num_samples = 2
    taps_per_sample[1] total taps per pair (8 metadata taps + N CIR taps)
                       With cir_num_samples=128  →  taps_per_sample = 128
    rfu[1]

    ── per-sample block, repeated num_samples times ──
    metadata[32]      (bytes 0-31 of each sample block)
      [0-3]   cir_counter         u32 LE   rolling frame counter
      [4-7]   rx_timestamp        u32 LE
      [8]     rx_gain_index       u8
      [9]     tx_gain_index       u8
      [10]    tx_pulse_shape_id   u8
      [11]    tap_resolution      u8  (bits [3:2]=bits, [1:0]=cm)
      [12-15] tx_timestamp        u32 LE
      [16]    rx_path             u8
      [17]    radar_mode_flags    u8  bits: [3:0]=mode [4]=single_pin
                                              [5]=dc_freeze [6:7]=rfu
      [18]    rx_antenna_id       u8
      [19]    tx_antenna_id       u8
      [20]    inter_pulse_dist_ns u8
      [21]    correlation_shift   u8
      [22-23] log2_deltaL / nsync u16 LE  (bits [5:0]=log2_deltaL,
                                            [15:6]=nsync_by_8)
      [24-25] peak_real_cir       u16 LE
      [26-27] num_pulses_used     u16 LE
      [28-29] cir_start_frac      u16 LE
      [30-31] cir_start_offset    u16 LE

    cir_data[N × bytes_per_tap]   (bytes 32 to block_size-1)
      3-byte tap format (default):
        real = int16 LE  bytes [0:2]
        imag = sign-extended int8  byte [2]
      4-byte tap format (high-res):
        real = int16 LE  bytes [0:2]
        imag = int16 LE  bytes [2:4]
      N = taps_per_sample - 8  =  120 (with taps_per_sample=128)

────────────────────────────────────────────────────────────────────────
3.  EXPECTED PACKET SIZES  (with default config)
────────────────────────────────────────────────────────────────────────

  num_samples      = 2   (RXC + RXB,  both paired with TX1)
  taps_per_sample  = 128
  actual_cir_taps  = 120
  bytes_per_tap    = 3 (default)  →  120 × 3 = 360 bytes CIR per sample
  block_size       = 32 + 360 = 392 bytes per sample
  UCI payload      = 10 + (2 × 392) = 794 bytes
  RADAR_FRAME hdr  = 8 bytes
  envelope         = 8 bytes
  Total UDP packet ≈ 810 bytes  at ~10.4 fps (96 ms interval)

  If the SR250 uses 4-byte taps:
  bytes_per_tap    = 4  →  120 × 4 = 480 bytes CIR per sample
  block_size       = 32 + 480 = 512 bytes
  Total UDP packet ≈ 1042 bytes

────────────────────────────────────────────────────────────────────────
4.  WHAT THE ETHERNET DUMP SHOWS  (Ethernet_Output_Structure_Dump.txt)
────────────────────────────────────────────────────────────────────────

  That capture was taken with 2 active RX antennas (IDs 1 and 2) and 1 TX.
  The SR250 batched 4 consecutive RFRI intervals into one notification:
    num_samples     = 8   (4 intervals × 2 RX antennas, cir_counter 5–8)
    taps_per_sample = 128  (actual CIR taps = 120)
    bytes_per_tap   = 4   (32-bit complex  →  480 bytes CIR / sample)
    block_size      = 512 bytes / sample
    Total payload   = 10 + (8 × 512) = 4106 bytes
  The session_handle in that capture = 0xF0000001.
  Decoded antenna pairs per interval: Sample[0] rx1/tx1, Sample[1] rx2/tx1.

5.  DYNAMIC SUMMARY
────────────────────────────────────────────────────────────────────────

  The uwb_cir_inspector ROS2 node writes a decoded-frames log to
  /tmp/session_summary.txt every time a CIR frame arrives.

  To watch it live:
    tail -f /tmp/session_summary.txt

  To view the full log after a session:
    cat /tmp/session_summary.txt
